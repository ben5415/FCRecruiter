# FCRecruiter 项目简介

## 项目概述

FCRecruiter 是一个面向足球游戏玩家和普通球迷的智能足球俱乐部管理与引援辅助平台。

在 Football Manager、EA Sports FC 等游戏或足球数据库中，用户往往需要浏览大量球员数据，手动判断阵容短板、战术需求和候选球员适配性。这个过程耗时较长，对不熟悉数据分析和足球战术的用户也不够友好。

FCRecruiter 将球员市场、球队阵容、战术、伤病事件和俱乐部知识整合到一个 Web 应用中，并在关键决策节点嵌入 Agent 分析能力，帮助用户回答两个核心问题：

1. 当前阵容有什么问题，应该优先补强什么位置？
2. 某名球员是否适合当前球队和战术？

Agent 负责整理上下文、解释数据和提出建议，但不会代替用户完成最终决策。

## 核心功能

- **球员市场**：搜索、筛选和分页浏览球员，查看球员详细信息。
- **球队阵容**：查看当前租户对应俱乐部的球员构成与位置分布。
- **战术管理**：记录球队当前阵型、打法和战术备注。
- **球队事件**：记录伤病、训练和更衣室事件，并根据角色控制操作权限。
- **智能招募建议**：结合阵容强度、位置深度、战术和伤病，生成补强方向与初步筛选条件。
- **球员适配分析**：针对具体候选球员，分析其战术作用、优势、风险及与现有阵容的关系。
- **知识库**：按租户维护足球知识，通过检索为分析提供补充依据。
- **多租户与角色权限**：每个租户对应一家俱乐部，支持经理、教练、球员和队医四类角色。

## Agent 设计

FCRecruiter 的 Agent 是嵌入业务流程的分析组件，而不是一个无边界的通用聊天机器人。

系统使用 LangChain Model 与 Tool Calling 构建轻量级 Agent Runtime，并将阵容、战术、伤病、球员筛选和知识检索封装为类型化 Tool。Agent 不直接访问业务数据库，也不能自行生成和执行 SQL，所有业务数据都需要通过受控的 Backend API 获取。

运行过程中，系统使用 Pydantic 校验工具参数和结构化报告，并限制模型执行步骤、工具调用次数与超时时间。当模型输出不合法或外部服务暂时不可用时，系统会返回可识别的降级结果，避免 AI 故障影响普通球员浏览功能。

## 推荐流程

```text
球队阵容、战术和伤病数据
          ↓
类型化工具获取业务上下文
          ↓
确定性代码统计阵容强度并筛选合法候选
          ↓
LLM 生成阵容诊断和适配解释
          ↓
结构化校验与 Evidence 整理
          ↓
用户查看依据并作出最终决定
```

其中，筛选、排序、权限、租户隔离和候选合法性由确定性代码负责；LLM 主要用于信息归纳、解释生成和权衡分析。

## 技术架构

项目由三个主要部分组成：

- **React + TypeScript 前端**：承载球员市场、阵容、战术、事件、知识库和分析结果页面。
- **FastAPI 业务 Backend**：负责账号、角色权限、租户隔离和足球业务数据，并向 Agent 提供受控内部接口。
- **独立 Agent Service**：负责 Agent Runtime、工具调用、知识检索、执行轨迹和离线评测。

主要技术栈：

`Python / LangChain / FastAPI / PostgreSQL / pgvector / React / TypeScript / Pydantic / Ollama`

## 项目特点

1. **从具体问题出发**：聚焦阵容诊断和引援筛选，不追求通用 Agent 能力。
2. **AI 最少但有效介入**：普通浏览不依赖模型，只在需要综合判断时触发分析。
3. **确定性逻辑与 LLM 分工**：硬约束由代码执行，模型不负责决定数据是否合法。
4. **可解释与可追溯**：报告保留球员数据、知识片段、假设和不确定性等 Evidence。
5. **安全的数据边界**：业务 Backend 统一实施鉴权、角色权限和租户隔离。
6. **可观测与可评测**：记录工具调用、Token、延迟、模型和 Agent 版本，并支持基础规则评测。

## 当前状态

项目已经打通基础招募分析流程：用户可以从球员市场生成球队补强建议，也可以进入具体球员页面生成适配分析。

目前更准确的定位是“可运行的技术与产品原型”。后续重点不是继续增加复杂 Agent 概念，而是完善建议筛选条件的落地、Evidence 展示、候选比较和用户反馈，并通过真实用户测试验证它是否确实降低了引援分析成本。
